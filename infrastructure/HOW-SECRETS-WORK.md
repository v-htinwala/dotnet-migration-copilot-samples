## ?? Flow Comparison

### Method 1: Local Development
```
You ? Create terraform.tfvars locally
    ? terraform apply reads it from disk
    ? Deploys to Azure
    ? terraform.tfvars stays on your computer (never commits)
```

### Method 2: GitHub Actions
```
You ? Store secrets in GitHub Settings
    ? Push .tf files to Git (no secrets)
    ? GitHub Actions runs
    ? Workflow injects secrets via -var flags
    ? terraform apply uses those values
    ? Deploys to Azure
```

## ?? Real Example from Your Workflow

```yaml
# .github/workflows/terraform-deploy.yml

- name: Terraform Plan
  run: |
    # GitHub injects secrets here at runtime
    terraform plan \
      -var="sql_admin_password=${{ secrets.SQL_ADMIN_PASSWORD }}" \
      -var="entra_client_id=${{ secrets.ENTRA_CLIENT_ID }}"
    #      ?                    ?
    #      Variable name        GitHub Secret (encrypted)
```

## ?? Step-by-Step: How It Actually Works

### Scenario 1: You Deploy Locally

```powershell
# Step 1: You create terraform.tfvars (one time)
cd infrastructure/terraform
echo "sql_admin_password = 'MySecret123!'" > terraform.tfvars

# Step 2: Deploy
terraform apply  # ? Reads terraform.tfvars from disk

# Step 3: Commit code (terraform.tfvars is blocked by .gitignore)
git add .
git commit -m "Updated infrastructure"
git push  # ? terraform.tfvars NOT pushed (gitignored)
```

### Scenario 2: GitHub Actions Deploys

```
# Step 1: You configure secrets in GitHub UI
GitHub ? Settings ? Secrets ? Add:
  - SQL_ADMIN_PASSWORD = "MySecret123!"

# Step 2: You push code
git push  # ? Only .tf files pushed, no secrets

# Step 3: GitHub Actions runs automatically
- Checks out code (no secrets in code)
- Reads secrets from GitHub Settings
- Passes to terraform via: -var="sql_admin_password=${{ secrets.SQL_ADMIN_PASSWORD }}"
- terraform apply runs with those values
- Deploys to Azure
```

## ?? Key Insights

1. **terraform.tfvars is optional** - Terraform can get values many ways
2. **GitHub Actions never sees terraform.tfvars** - It uses Secrets instead
3. **Secrets are encrypted in GitHub** - More secure than files
4. **Multiple input methods** - Terraform is flexible about where it gets values
5. **Priority order matters** - Command-line vars override file vars

## ? Common Questions

**Q: Can I commit terraform.tfvars if I encrypt it?**
A: No! Even encrypted, it's risky. Use GitHub Secrets or Key Vault instead.

**Q: What if I accidentally commit terraform.tfvars?**
A: 
1. Remove it immediately: `git rm --cached terraform.tfvars`
2. Rotate all secrets in the file
3. Push the removal

**Q: How do I share terraform.tfvars with my team?**
A: Don't! Instead:
- Use `terraform.tfvars.example` with dummy values (committed)
- Share secrets via secure channel (1Password, Azure Key Vault)
- Each team member creates their own local terraform.tfvars

**Q: Can I see the secrets in GitHub Actions logs?**
A: No! GitHub automatically masks secret values in logs:
```
terraform apply -var="password=***"  ? Hidden in logs
```
